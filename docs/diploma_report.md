# Отчет по выполненным работам в проекте BKI Document Portal

## Введение

В рамках проекта разработана программная система для интеллектуального поиска и работы с внутренними документами. Решение ориентировано на использование в корпоративной среде и объединяет технологии обработки документов, векторного поиска, генерации ответов на основе LLM, а также web-интерфейс для пользователей и администраторов.

Архитектурно проект разделен на две крупные части:

1. AI-часть, включающую сервис Retrieval-Augmented Generation (RAG), обработку документов, построение эмбеддингов, векторный поиск, интеграцию с локальной LLM и механизмы контроля качества ответа.
2. WEB-часть, включающую backend портала, frontend-интерфейс, пользовательские сценарии просмотра документов, чат с моделью и административную панель управления базой знаний.

В ходе анализа кодовой базы установлено, что проект развертывается как набор контейнеризированных сервисов: PostgreSQL с расширением `pgvector`, `Ollama`, AI backend (`backend`), backend портала (`portal_backend`) и frontend (`portal_frontend`). Оркестрация осуществляется через [docker-compose.yml](C:\Users\koh0\Documents\bki_system\docker-compose.yml).

## Общая характеристика реализованной системы

Разработанное решение представляет собой корпоративный портал доступа к документам с функциями интеллектуального поиска по содержимому. Пользователь может загрузить документы, индексировать их, выполнять поиск по всей базе или по отдельному документу, получать ответ LLM на основе найденного контекста и переходить к первоисточнику.

Ключевые особенности системы:

- поддержка форматов `PDF` и `DOCX`;
- разбиение документов на чанки с сохранением привязки к страницам;
- построение эмбеддингов через локальный сервис `Ollama`;
- хранение векторов в PostgreSQL/`pgvector`;
- гибридный поиск: семантический, полнотекстовый и literal-поиск;
- генерация ответа на основе найденных фрагментов документа;
- самопроверка ответа на предмет опоры на контекст;
- разграничение доступа по ролям `user` и `admin`;
- web-портал с чат-интерфейсом, просмотром документов и административной панелью.

### 1.2. Реализация схемы хранения данных для RAG

В проекте реализована полноценная SQL-схема для хранения документов, чанков, эмбеддингов, пользователей, ролей, событий запросов и обратной связи. Основная схема описана в [schema/01_init.sql](C:\Users\koh0\Documents\bki_system\schema\01_init.sql).

В рамках AI-части реализованы следующие сущности:

- `source_documents` для хранения метаданных исходных документов;
- `text_chunks` для хранения текстовых фрагментов и векторных представлений;
- `ask_events` для фиксации фактов обращения к RAG-системе;
- `feedback` для оценки качества ответов;
- `audit_log` для журналирования действий и редактированных данных;
- таблицы пользователей и ролей для управления доступом.

Особую роль играет таблица `text_chunks`, в которой:

- хранятся эмбеддинги размерности `768`;
- автоматически формируется `tsvector` для полнотекстового поиска;
- создается HNSW-индекс для ускорения векторного поиска по косинусной близости.

Таким образом, была выполнена не только логическая, но и физическая подготовка БД к работе в режиме гибридного retrieval.

### 1.5. Реализация гибридного retrieval

Одним из наиболее значимых результатов AI-части является реализация гибридного поиска, который сочетает несколько стратегий извлечения релевантного контекста. Логика retrieval находится в [backend/app/rag/retrieval.py](C:\Users\koh0\Documents\bki_system\backend\app\rag\retrieval.py).

Реализованы три механизма поиска:

- `similarity_search` для семантического поиска по эмбеддингам;
- `keyword_search` для полнотекстового поиска через `tsvector` и `websearch_to_tsquery`;
- `literal_search` для точечного поиска технологических терминов и литеральных вхождений.

Далее результаты объединяются в `merge_retrieved_chunks`, где:

- устраняются дубликаты;
- сохраняется приоритет точных совпадений;
- не теряется семантический recall.

Это решение повышает качество выдачи в случаях, когда вопрос пользователя содержит одновременно естественный язык и точные термины, например названия технологий, идентификаторов или регламентных сущностей.

### 1.6. Реализация RAG-оркестрации и генерации ответа

Основная логика ответа на пользовательский запрос реализована в [backend/app/rag/orchestrator.py](C:\Users\koh0\Documents\bki_system\backend\app\rag\orchestrator.py).

Выполнены следующие элементы:

- получение релевантных чанков через retrieval;
- формирование контекста с явными ссылками вида `[source1]`, `[source2]`;
- сборка системного и пользовательского промпта;
- вызов LLM с температурой `0.0` для уменьшения вариативности;
- возврат ответа и списка источников в API.

Шаблоны промптов вынесены в [backend/app/rag/prompts.py](C:\Users\koh0\Documents\bki_system\backend\app\rag\prompts.py). На уровне промпта модели явно запрещено выходить за рамки предоставленного контекста, что снижает вероятность галлюцинаций.

### 1.7. Механизм самопроверки ответа

Дополнительно реализован механизм верификации ответа LLM. После формирования ответа система повторно обращается к модели с задачей оценить, подтверждается ли сгенерированный текст исходным контекстом. Если поддержка контекстом не подтверждается, ответ заменяется на сообщение о недостаточности информации.

Данный механизм является важным исследовательским и инженерным результатом, поскольку повышает надежность работы RAG-системы в условиях корпоративного использования.

## Заключение

Проведенный анализ показывает, что проект BKI Document Portal реализован как комплексная двухконтурная система, в которой AI-часть и WEB-часть логически разделены, но технологически тесно интегрированы.

По AI-направлению выполнены работы по созданию RAG-инфраструктуры, индексации документов, векторному и гибридному поиску, интеграции локальной LLM, обеспечению безопасности и аудита. По WEB-направлению выполнены работы по разработке backend-портала, frontend-приложения, пользовательского чата, просмотру документов и административной панели управления.

В результате создана функциональная система, позволяющая:

- централизованно загружать и хранить документы;
- выполнять интеллектуальный поиск по содержимому;
- получать ответы LLM с указанием источников;
- проверять основания ответа через просмотр исходного фрагмента;
- управлять базой знаний через web-интерфейс.

С инженерной точки зрения проект можно охарактеризовать как практически завершенный MVP корпоративной документной RAG-системы с выделенной AI-частью и отдельным WEB-контуром.
